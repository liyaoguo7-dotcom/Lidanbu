## 一、好友邀请与二维码加入

| 事项 | 结论 | 依据 |
|---|---|---|
| 转发给微信好友 | **能** | 客户端 `onShareAppMessage` / `wx.shareAppMessage`；页面声明回调后右上角菜单与 `open-type="share"` 按钮可调起 |
| 分享到朋友圈 | **能** | `onShareTimeline` 回调 |
| 二维码/小程序码加入 | **能** | 服务端接口：`wxa/getwxacode`（少量）、`wxa/getwxacodeunlimit`（不限量，适合邀请场景）、`wxaapp/createwxaqrcode`（普通二维码）。来源：微信开放文档 服务端 API 列表页 |
| 邀请链接带参 | **能** | 小程序码支持 scene 参数；转发支持 path 带参 |

**对家庭共享设计的影响**：v3.1 8.2"微信好友或二维码发出邀请"两条路都走得通。建议：邀请用 `getwxacodeunlimit` 生成带邀请参数的小程序码（不限量，适合每邀请一张码）。

## 二、微信登录

| 事项 | 结论 | 依据 |
|---|---|---|
| 微信登录 | **能** | `wx.login()` 取 code → 服务端 `code2Session`（`sns/jscode2session`）换 openid/session_key。来源：微信开放文档 code2Session 页 |
| 云开发免服务端登录 | **能** | 开通云开发后，云函数内 `cloud.getWXContext()` 直接取 OPENID/APPID，无需自建服务器换 code |

**说明**：v3.1 17.1"微信登录；记录绑定账户存服务端"与云开发方案天然契合，无需自建登录服务器。

## 三、Excel 文件发送与下载

| 事项 | 结论 | 依据 |
|---|---|---|
| 把 Excel 发给微信好友 | **能（有限制）** | `wx.shareFileMessage` 可把文件发给好友；支持的文件格式与大小上限以官方文档为准，`.xlsx` 为办公常见格式 |
| 用户下载 Excel 到手机 | **能（有限制）** | `wx.downloadFile` 下载到本地；iOS/Android 落盘路径与打开方式有差异，需真机验证 |
| 在小程序内直接打开预览 | **能（有限制）** | `wx.openDocument` 可打开 office 文档预览；大文件/复杂格式渲染以真机为准 |

**对导出设计的影响**：v3.1 第十章"导出 Excel（.xlsx）＋发送至微信"可行。注意：文件有效期（第 19 章待确认 #12）若用云存储临时链接，需按云存储 TTL 设计。

## 四、分享限制

| 事项 | 结论 | 依据 |
|---|---|---|
| 诱导分享 | **不能** | 微信审核规范 3.2.1：含诱导分享/诱导关注/利益诱惑分享的小程序会被拒绝。来源：`developers.weixin.qq.com/miniprogram/product/reject.html` |
| 获知用户是否完成分享 | **不能** | 微信分享接口不再返回分享结果事件；无法用分享做强制任务校验（据 36氪转引"知晓程序"报道，属历史调整，现状以最新客户端为准） |
| "分享转发"入口 | **能** | v3.1 第七章"分享转发（调起微信分享）"为普通转发能力，不违规 |

**对设计的影响**：家庭共享邀请、导出发送必须做成用户主动行为，不得加"分享后才可XX"的门槛。

## 五、隐私政策与账号注销的平台要求

| 事项 | 结论 | 依据 |
|---|---|---|
| 必须有隐私政策 | **平台要求有** | 审核规范 3.4.1：收集使用用户数据须明确告知用途、经用户明确同意。SDK 个人信息保护规则要求开发者制定并公布隐私政策 |
| 注销后删除数据 | **平台要求有** | 审核规范 3.4.1："在用户注销账号后应相应删除相关数据" |
| 账号注销入口 | **平台要求有** | 审核规范 3.5.5：有账户系统必须提供"能正常使用且易于发现"的退出/注销选项 |
| "我的"页底部小字 | **符合要求** | v3.1 第七章"最底部不起眼小字'隐私政策｜注销账号'"满足"易于发现"要求；具体文案以上线前审核规范为准 |

**待办**：隐私政策正文、注销流程（删哪些数据、缓冲期）需在阶段 3 前由用户/法务确认；注销实现时注意 v3.1"删除永久、审计留痕"的平衡（审计日志是否随账号删，待定）。

## 六、会员收费方式验证（新增）

### 6.1 小程序里能否直接售卖会员（虚拟服务）

**能，但必须走官方"小程序虚拟支付"，不能用普通微信支付直收，也不能引导外部付款。**

- 微信开放文档《虚拟支付》："开发者在小程序内提供的虚拟商品（包括虚拟货币、**解锁功能、订阅内容、付费功能**、打赏、购买虚拟礼物等），**购买和支付均需接入小程序虚拟支付**"。礼单簿的"会员（扩大额度＋拍照导入＋红字礼簿）"属于"解锁功能/订阅内容"，落在此范围内。
- 来源页：`developers.weixin.qq.com/miniprogram/dev/platform-capabilities/business-capabilities/virtual-payment.html`

### 6.2 iOS 与安卓的规定是否不同

**是，不同，且差异大。**

| | Android / 鸿蒙 / Windows | iOS |
|---|---|---|
| 支付通道 | 微信支付 | **Apple 支付（苹果内购）** |
| 发起 API | `wx.requestVirtualPayment`（平台按设备自动路由） | 同一 API，平台路由到 Apple 支付 |
| 用户端要求 | 基础库 2.19.2+ | 微信客户端 **8.0.68+**、iOS **15+**、仅**中国大陆 App Store 账户**、**最低支付金额 1 元** |
| 沙箱测试 | 支持沙箱 | **Apple 支付不支持沙箱，仅支持现网** |
| 结算周期 | **T+3**（3 日后分账，可提现） | 苹果**自然月结束后 45～60 天**结算，扣 Apple 佣金后经腾讯划转给开发者 |
| 额外开通条件 | 无 | 需先开通虚拟支付＋**配置小程序简称**（Apple 展示 display name 用） |

- 来源页：上文虚拟支付页 §1.4、§2.2；iOS 适配页 `.../virtual-payment/ios.html`

### 6.3 可行的收款方式

| 方式 | 可行性 | 说明 |
|---|---|---|
| 小程序虚拟支付（道具直购） | **可行（官方唯一通道）** | 会员档位做成"道具"上架，用户购买后服务端发货开通会员。个人主体官方建议只做道具直购（见下） |
| 普通微信支付商户号直收 | **不可行** | 虚拟商品必须走虚拟支付；用实物支付通道收虚拟费用属违规 |
| 客服消息引导外部付款/H5 付 | **不可行** | 2026年4月1日起，售卖虚拟商品须全终端走官方虚拟支付，不得引导用户去外部网页/公众号/App 付款。**此条来自第三方解读，未见官方原文，签约前须复核** |
| 代币（充值点数再消费） | 可行但不建议 | 个人主体场景官方建议只做道具直购，链路更简单 |

### 6.4 对主体类型和类目的要求

**企业 / 事业单位 / 个体工商户**：
- 条件：已认证小程序；主体为企业/事业单位/个体工商户；主体信息完备
- 来源：虚拟支付页 §1.1 开通条件

**个人主体**：
- 据第三方解读文章（wuyi.wiki，2026-09 左右发布），2026年8月底前后微信开始向个人主体开放虚拟支付，条件约三条：
1. 小程序主体为个人，开发者持有**中国大陆居民身份证**
2. 服务类目包含**「工具」**
3. 已完成**微信认证**与**备案**
- 同文称：个人主体**月支付限额 10 万元**；不支持需电信业务资质的服务；安卓技术服务费约 **1%**（平台限时优惠）；iOS 走苹果内购约 **12%**（为苹果佣金，腾讯 5% 技术服务费 2026 年暂免）
- **以上个人主体内容全部来自第三方解读，未见微信官方原文；注册/签约前必须以微信公众平台后台与开放文档复核，费率以签约页为准**

### 6.5 对礼单簿的结论

1. 会员收费**技术上可行**：虚拟支付道具直购即卖会员档位；iOS/Android 双端官方已打通（道具双端互通）。
2. **主体是关键变量**：若用户以个人主体注册，走个人虚拟支付（待官方复核）；若注册个体工商户/企业，走标准企业虚拟支付。两种的主体资质、费率、限额都不同，**定价前必须先定主体**。
3. **iOS 成本与账期**：iOS 结算慢（45～60 天）且有苹果佣金，定价模型里要计入；最低 1 元限制影响低价档位设计。
4. **类目**：个人主体须选「工具」类目——礼单簿记账工具属性吻合，但注册时类目必须一次选对。
5. **不做外部引流付款**：任何"加客服微信转账开通会员"都是违规红线。

## 附记（2026-10-20 复核更正）

§6.4 中个人主体虚拟支付原标注"来自第三方解读，未见官方原文"。2026-10-20 已在微信开放文档核实到官方专页《虚拟支付：个人》（developers.weixin.qq.com/miniprogram/dev/platform-capabilities/business-capabilities/virtual-payment/person），原文要点：

- 平台"将在符合条件的类目范围内，向个人主体小程序开放虚拟支付能力"
- 开通条件：个人主体（持居民身份证）＋服务类目含「工具」＋已完成小程序认证、备案
- 个人主体月支付限额 10 万元；不支持需电信业务资质的服务
- 费率：Android 等腾讯技术服务费 1%；iOS 为 Apple 佣金 12%
- 结算：Android T+3；iOS 约 45–60 天；iOS 退款由用户向 App Store 申请
- 接入方式为道具直购（short_series_goods），与 §6.3 结论一致

结论更新：礼单簿类目「工具 > 记账」符合个人通道类目要求，**个人主体路线现已官方确认可行**（月限额内）；个体户/企业路线无月限额。主体选择仍由用户决定，定价前先定主体这条不变。认证费现行分档：个人 30 元，企业/个体工商户 300 元（有效期一年）。
