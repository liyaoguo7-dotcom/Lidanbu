# OCR 腾讯云接入（AQ批）

拍照导入的真实文字识别接腾讯云 OCR。本文件写清：密钥怎么配、代码怎么选、
真机拿什么验。**当前状态：代码已接通并通过本地打桩测试；真实调用待填
密钥后由管理员真机首验，未验之前不算"已通"。**

## 一、识别实现选择（服务端决定，客户端无感）

识别只在云函数 `api` 里发生（`cloudfunctions/api/tencent-ocr.js`），
每次 `importer.startImportTask` 由服务端按下面三格选实现，结果回标在
任务返回的 `adapter` 字段（`'tencent'` / `'mock'`，日志同口径）：

| 条件 | 实际识别 |
|---|---|
| 环境变量未配置密钥 | MockOCR（假数据，行为与接入前一致） |
| 已配置密钥、调用者非管理员 | MockOCR（公开开放等用户发话） |
| 已配置密钥、调用者是管理员 | 腾讯云真实识别 |

管理员口径与全站一致：appConfig 文档 `adminIds`（云端档）＋
`addedAdminIds`（后加档）名单内的 openid。

接口与策略：先调印刷体 `GeneralBasicOCR`；印刷体没认出任何文字时再调
手写体 `GeneralHandwritingOCR` 兜底；任务带 `mode='handwriting'` 时只调
手写体、带 `mode='print'` 时只调印刷体。两次都空 → 按"没认出来"处理
（识别失败，既有口径：不扣积分）。识别结果按冻结契约整理：左栏在前、
栏内自上而下、行内碎片按 X 拼接；只有姓名的行金额留空、只有金额的行
姓名占位，不丢行，最后进核对页由用户改。

## 二、环境变量清单（只填云函数，不进代码/仓库）

给云函数 **api** 填三个环境变量：

| 变量名 | 必填 | 说明 |
|---|---|---|
| `TENCENT_SECRET_ID` | 是 | 腾讯云 API 密钥 ID |
| `TENCENT_SECRET_KEY` | 是 | 腾讯云 API 密钥 Key（只显示一次，妥善保存） |
| `TENCENT_OCR_REGION` | 否 | 地域，缺省 `ap-guangzhou`，一般不用填 |

任一必填缺失＝未配置，系统自动回落 Mock，不会报错、不会乱扣费。

**填写位置**：微信开发者工具 → 云开发控制台 → 云函数 → `api` →
配置 → 环境变量，逐个添加后保存，并**重新部署 api** 才生效。

## 三、腾讯云控制台侧步骤大纲

1. 用小程序同主体的腾讯云账号登录腾讯云控制台，开通「文字识别 OCR」
   服务（产品页搜"文字识别"，按指引开通；通用印刷体/手写体在同一服务下）。
2. 访问管理 → API 密钥管理 → 新建密钥，得到 SecretId / SecretKey；
   （更稳妥的做法：建一个子用户并只授予 OCR 相关权限，用子用户密钥。）
3. 把密钥按第二节填进 api 云函数的环境变量——**不要发到聊天里、不要
   写进代码、不要截图外传**；填完重新部署 api。
4. 在腾讯云控制台确认 OCR 有可用额度（新开通一般有免费额度；超出后
   约 0.1 元/次量级，以控制台价格页为准）。

## 四、真机验收清单（填密钥＋部署后，管理员身份验）

样张准备：**约 10 张印刷体礼单＋约 10 张手写礼单**真实照片（脱敏可，
但版式要真）。逐项看：

- [ ] 管理员手机拍照导入：识别结果进核对页，`adapter` 走真实识别
      （结果明显来自照片内容，不是罐头"张三/李五/王二麻"）
- [ ] 顺序：多列礼单按左列→右列、列内自上而下，不从右列开始
- [ ] 完整性：认不出的行有没有被丢（应保留空行让用户补）
- [ ] 金额位数：千元/万元、带角分小数、千分位逗号是否读对
- [ ] 手写潦草：连笔、简写姓名能认到什么程度（记录错例）
- [ ] 红纸礼单：红底黑字/红底金字的识别率
- [ ] 竖排礼单：竖写姓名金额的顺序与拆分
- [ ] 识别失败时：不扣积分、提示"没认出来"可重拍
- [ ] 非管理员账号：仍走 Mock（罐头结果），不触发真实识别
- [ ] 扣分：真实识别成功仍只扣 5 分一次，重复提交不重复扣

重点盯四类错：**手写潦草、红纸、竖排、金额位数**——这四类最容易翻车，
错例截图留存，作为调解析/换接口的依据。

## 五、已知边界

- 照片送达链路（AR批已补）：云模式下客户端在启动导入任务**之前**，
  先把照片按拍照顺序上传到云存储 `ocr-imports/` 前缀下（路径含时间戳
  与随机段），任务入参只传 fileID 数组（`imageFileIds`），服务端逐张
  按 fileID 取图识别、结果按序拼接；本地临时路径不再走云端。上传
  任一张失败 → 页面直接报「照片上传失败」，不启动任务、不扣分。
  真机首验若识别结果不对，先看 api 日志的 `adapter` 标记与上传是否
  成功，再怀疑识别本身。本地演示模式不上传，行为不变。
- 照片留存：导入在核对页**确认写入成功后**，客户端会删除本次上传的
  这批 `ocr-imports/` 照片（尽力而为，删除失败不影响导入结果）；
  用户中途放弃核对（未确认写入）的照片会留在云存储 `ocr-imports/`
  下，目前没有自动清理——**待定清理策略**（如按前缀定期清理），
  定版前请勿把该目录当长期图床使用。
- 姓名/金额被厂商拆成两个独立文本块时，解析器有"同行碎片合并"与
  "金额栏/姓名栏窄守卫合并"两道恢复；极端版式仍可能拆错，核对页可改。
- 图片过大时腾讯云有大小限制（ImageBase64 约 10MB 级），拍照走压缩图
  一般无碍；超限会按识别失败处理，不扣分。
