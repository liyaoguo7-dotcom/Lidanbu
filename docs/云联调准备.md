## 二、数据库：集合、权限规则、索引

### 2.1 权限原则（为什么这么配）

礼单簿的权限模型是**服务端逐条校验**：小程序端不直接读写数据库，全部请求走云函数 `api`，云函数里用 `core/authz.js` 判断"这条数据是不是你的、你有没有被授权、有没有这个开关"。所以数据库层面给用户端**一律关死**最安全——云函数用管理员权限访问数据库，不受安全规则限制，关死不影响云函数工作。

### 2.2 逐集合照配（云开发控制台 → 数据库 → 选集合 → 权限设置 → 自定义安全规则）

17 个集合**全部**填同一条规则：

```json
{ "read": false, "write": false }
```

含义：任何用户端直连数据库的读写都被拒绝；只有云函数能碰数据。

| 集合 | 用途一句话 | 除统一规则外的特别说明 |
|---|---|---|
| users | 用户与会员状态 | — |
| contacts | 亲友录（姓名+备注） | — |
| receiveEvents | 收礼礼薄 | — |
| receiveRecords | 收礼记录 | — |
| giftRecords | 送礼记录 | — |
| shareMemberships | 家庭共享成员关系 | — |
| shareGrants | 授权开关与范围 | — |
| auditLogs | 审计流水（不含金额/姓名原文） | 只许云函数追加写，任何端不得改删（统一规则已覆盖） |
| importJobs | 拍照导入任务 | — |
| exportJobs | 导出历史 | — |
| appConfig | 全局配置单例 | **谁都不能从用户端改**：管理员名单 adminIds 只能在控制台手动维护或经老板平台接口（云函数内二次校验管理员）修改；统一规则已覆盖 |
| inviteBindings | 邀请绑定关系 | 注销不删，防重复计数 |
| inviteRewardGrants | 邀请奖励发放记录 | 额度唯一真源，只许云函数写 |
| orders | 会员购买订单（金额快照+渠道单号） | 只许云函数写；发货必须先验签并比对金额与快照一致，重复回调幂等 |
| notifications | 站内通知 | 只许云函数写；标记已读走云函数按本人校验 |
| feedbacks | 意见反馈 | 提交走云函数；老板平台列表只读状态与正文，不含账本内容 |

### 2.3 索引建议（控制台 → 数据库 → 选集合 → 索引管理 → 添加）

| 集合 | 索引字段 | 用途 |
|---|---|---|
| contacts | ownerId ↑ + createdAt ↓ | 按主人拉亲友录 |
| receiveEvents | ownerId ↑ + createdAt ↓ | 按主人拉礼薄列表 |
| receiveRecords | eventId ↑ + createdAt ↓；另加 contactId ↑、ownerId ↑ + date ↓ | 礼薄内记录、按人往来、按主人统计 |
| giftRecords | ownerId ↑ + date ↓；另加 contactId ↑ | 送礼列表与往来 |
| shareMemberships | ownerId ↑ + status ↑；另加 memberId ↑ + status ↑ | 主人看成员、成员看"我加入的账本" |
| shareGrants | membershipId ↑ | 按成员关系取授权单 |
| auditLogs | ownerId ↑ + createdAt ↓ | 老板平台/审计回溯 |
| importJobs / exportJobs | ownerId ↑ + createdAt ↓ | 任务历史 |
| inviteBindings | inviteeId ↑（唯一）；另加 inviterId ↑、code ↑ | 防重复绑定、按邀请人统计 |
| inviteRewardGrants | userId ↑ + grantedAt ↓；另加 invitedUserId ↑ | 按邀请人算额度池、防重复发放 |
| users | inviteCode ↑（稀疏） | 按邀请码找邀请人 |
| orders | userId ↑ + createdAt ↓；outTradeNo ↑（唯一）；channelTradeNo ↑ | 我的订单、回调按业务单号定位、渠道单号对账 |
| notifications | userId ↑ + read ↑ + createdAt ↓；dedupeKey ↑ | 未读红点与列表、防重复发通知 |
| feedbacks | status ↑ + createdAt ↓；userId ↑ | 老板平台按状态看反馈 |
| pointsLedger | userId ↑ + createdAt ↓；唯一约束见 2.4 | 我的积分流水、幂等对账 |

### 2.4 唯一索引与幂等约束（任务AF 清单；上线前必建）

幂等目前全部由代码保证（先查后写），**不是数据库原子约束**：并发/重试下
理论上有重复入账的缝，唯一索引是上线前的兜底。init 初始化脚本**建不了
索引**（云函数没有建索引的接口），以下索引一律在控制台手动建。

| # | 约束 | 集合与字段 | 代码级现状（已核实） |
|---|---|---|---|
| 1 | 积分流水只入账一次 | `pointsLedger`：userId ↑ + kind ↑ + refId ↑（**唯一**） | `core/points` 的 grant/spend/refund 写前先按 (userId,kind,refId) 查流水，命中即返回首次结果；现行全部写入口都带 refId（拍照 `import:<jobId>`、套餐赠分=订单号、退款=`<原refId>:refund`） |
| 2 | 邀请奖励只发一次 | `inviteRewardGrants`：invitedUserId ↑（**唯一**）；`inviteBindings`：inviteeId ↑（**唯一**） | 绑定前双查（绑定表 + 历史发放记录，注销后也不重复计）；发放前再按 invitedUserId 查一次 |
| 3 | 订单业务单号不重复 | `orders`：outTradeNo ↑（**唯一**） | 单号 = 时间 + 随机生成；支付回调按 outTradeNo 定位订单，已 paid 的重复回调直接返回、不重复发货 |
| 4 | 注册赠分只发一次 | 由第 1 条复合唯一索引覆盖（kind=`register_grant`、refId=`register:<userId>`） | 建号走 grantRegisterBonus → grant 幂等；服务端 ensureServerUser 与本地 ensureUser 同口径 |

**控制台建唯一索引的步骤**（每个索引重复一遍）：

1. 云开发控制台 →「数据库」→ 左侧选集合（如 `pointsLedger`）；
2. 上方切到「索引管理」→「添加索引」；
3. 按上表逐个添加字段并选排序方向（升序 ↑），字段顺序照表里写的来；
4. 勾选「唯一索引」→ 确定，等状态变为生效；
5. 若提示建失败，多半是存量已有重复数据：先按同字段组合查出重复行、
   核对后删多余的（积分流水删前先对账余额），再重建。

> 注意第 1 条：若将来出现 refId 为空的同类流水（如手工补分），唯一索引
> 会把第二条挡下报错——手工补分一律要带业务 refId，不允许空着写。

## 三、初始化脚本

- 位置：`cloudfunctions/init/`（`index.js` + `package.json` + `README.md`）。
- 做什么：建齐 17 个集合；写入 `appConfig` 单例默认配置——免费额度 3/50/50/50（2026-10-24 用户改定：每礼薄与送礼 30→50）、会员到期规则（缓冲 30 天、提醒三次）、会员专属清单、邀请奖励默认（开启，+10/+5，上限 10 次）、`adminIds: []`。
- 管理员初始化：跑完脚本后，按 README 把创始人 openid 填进 `adminIds`；不填 = 无人能进老板平台（故意的安全默认）。
- 可重复调用：已有集合/配置会跳过，不覆盖老板平台改过的值；初始化完成后删除该云函数。
- 会员额度数字目前是占位，定价时在老板平台或控制台改配置即可，不用改代码、不用重跑初始化。

## 四、云存储目录规划与访问规则

控制台 → 存储 → 新建以下目录（规则在存储的权限设置里按目录或全局配；语法细节以控制台当时提供的规则模板为准）：

| 目录 | 放什么 | 谁能读 | 谁能写 |
|---|---|---|---|
| `fonts/` | 三款横置字体包：`lxgw-wenkai.woff2`、`mashanzheng.woff2`、`longcang.woff2`（✅ 2026-10-23 已上传，`CLOUD_FONT_BASE` 已填真实 cloud:// 地址；客户端来源顺序为缓存→云存储下载→分包兜底——安卓微信无法加载分包内字体文件，云下载是安卓的正路，下载一次后走本地缓存） | 所有人可读（字体文件无隐私） | 仅管理员经控制台上传 |
| `examples/` | 收礼/送礼"点击查看示例"用的正式版截图 | 所有人可读 | 仅管理员经控制台上传 |
| `exports/` | 用户导出的 xlsx（若导出改走云存储方案） | **仅文件所属用户本人**（按上传时记录的 openid 限制，规则示意：`auth.openid == resource.openid`） | 仅云函数写入 |
| `imports/` | 拍照导入的用户照片（OCR 接入后启用） | **仅本人**（同上） | 仅云函数/本人上传通道写入；识别完成后按隐私政策口径删除（OCR 数据处理口径定了以后在此写明保留时长） |

规则要点：`fonts/`、`examples/` 公开读没问题；`exports/`、`imports/` 装的是用户账本内容和照片，**绝不能公开读**，也不能用"所有登录用户可读"——必须收紧到本人。

## 五、联调测试清单（逐条做，逐条勾）

> 每条都写了"怎么做 / 期望什么"。任何一条不过，先停下记录现象（截图+云函数日志），不要跳着往下走。

### 1. 登录
- 怎么做：真机（或模拟器登录态）打开小程序，触发任意云请求；去控制台看云函数 `api` 的日志与 `users` 集合。
- 期望：云函数日志里 `cloud.getWXContext().OPENID` 与 `users` 里新建的 `_id` 一致；重复打开不重复建号；昵称头像不授权也能正常用。

### 2. 记账（收礼/送礼/亲友）
- 怎么做：新增 1 位亲友 → 建 1 个礼薄 → 记 2 条收礼 → 记 1 条送礼；再各改一次、各删一次。
- 期望：控制台对应集合里数据同步增改删；金额以"分"整数存储（如 1000 元 = 100000）；列表、往来页数字与手算一致；删亲友时弹窗数字（连带 X 条收礼、Y 条送礼）与实际删除条数一致。

### 3. 家庭共享邀请
- 怎么做：用第二个微信号当家人：主人（会员）勾选权限与范围发邀请 → 家人接受 → 家人分别试看、新增、修改、删除、导出；然后主人改一次权限、再移除成员。
- 期望：没勾的权限家人做了被拒且提示可读；成员视角往来页只统计已授权部分并显示"仅统计已授权给你的记录"；改权限立即生效；移除后家人立刻进不去，他加的记录还在主人账本且标着 createdBy；主人会员过期进缓冲期时家人只读、不能新邀请。

### 4. Excel 导出
- 怎么做：主人导出全部 → 微信里打开文件核对；成员在"可导出"关时试导出、开时再导一次。
- 期望：xlsx 能打开，列与金额（数值单元格、两位小数格式）正确；成员关时被拒、开时文件里只有已授权部分；`exportJobs` 里每次成功导出有一条记录，被拒的不写记录。

### 5. 字体下载（横置）
- 怎么做：真机进横置礼单本，依次切三款字体；杀掉小程序重进再切一次；开飞行模式再切一款没下过的字体。
- 期望：首次切换有下载并渲染成对应字体；重进时走缓存不再重复下载；离线/失败时自动回退系统楷体/宋体、**不出方框**，恢复网络后可再下；姓名、金额、"礼金"随字体变，"贺礼/奠仪"恒为宋体。

### 6. 邀请奖励
- 怎么做：新微信号用邀请人的码绑定 → 先不记账看邀请人奖励（应无变化）→ 新号建礼薄记 1 条收礼 → 回邀请人"我的—邀请奖励"看额度；再让新号重复触发一次；两个新号用同一台设备试第二次领取。
- 期望：条件完成才发放 +10/+5 且额度立刻可用（能多记 10 条收礼）；重复触发不重复发；同设备第二次被拒；邀请人额度池在老板平台统计里对得上；全程没有任何"必须分享"类文案或拦截。

### 7. 会员状态
- 怎么做：在控制台手动把测试号 `users.membership` 改成 member 并设到期时间（虚拟支付接入前的临时办法，接入后改走真实购买）；分别测会员中、刚到期、缓冲期内、缓冲期后四种状态。
- 期望：会员中额度按会员数、能发起共享邀请、能进横置与拍照导入；到期后额度回免费数、超额记录只读；缓冲期内家人只读；缓冲期后共享暂停、数据还在，续费（再改回 member）自动恢复；横置里选过的字体/样式在到期—续费全程不丢。

### 8. 老板平台读写
- 怎么做：用 `adminIds` 里的号进老板平台（"我的"页版本号连点 5 次入口），改一次免费额度数字和邀请奖励上限；用不在名单里的号试进一次；改完回小程序验证生效。
- 期望：管理员能改、改完即时生效；非管理员被拒（提示"需要管理员身份"）且配置一字未变；每次修改在审计里有记录（action=config）；老板平台任何页面都看不到具体礼金、联系人、备注。

### 10. 通知 / 反馈（收官新增面）
- 怎么做：触发一条会员到期通知与一条邀请奖励到账通知；再提交一条意见反馈。
- 期望：通知只发给本人、红点未读数正确、重复触发不重复发（dedupeKey）；反馈进 `feedbacks` 且老板平台反馈列表能看到（只有正文与状态，无账本内容）。
- 电子请柬已改为跳转合作小程序（自制请柬 2026-10-21 取消，invitations/rsvps 集合已下线）：联调时只需确认首页入口在配置 AppID 后能跳过去、未配置时提示「敬请期待」，无集合与权限事项。

### 11. 并发与越权（安全抽查）
- 怎么做：两台手机同时往同一礼薄加记录；用未被授权的号直接调云函数试读别人的礼薄（云端测试伪造参数）。
- 期望：两条记录都在、不丢；越权请求被服务端拒绝（不靠前端藏按钮）。
