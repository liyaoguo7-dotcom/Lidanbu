# 开通云开发与联调清单（大白话版）

> 拿到正式 AppID 之后，一步一步把小程序从"本地演示"变成"真能用的"。
> 前提：已按《注册小程序指引-企业主体.md》拿到正式 AppID。

---

## 第一部分：开通云开发环境

1. 微信开发者工具打开本项目，AppID 换成**正式 AppID**（项目设置里改）。
2. 点工具栏上的**「云开发」**按钮，按页面提示开通（第一次会让你创建一个环境，起个名字如 `lidanbu-prod`）。
3. 开通成功后，复制**环境 ID**（一串类似 `lidanbu-prod-xxxxx` 的字符）。
4. 打开 `miniprogram/config/app-config.js`，把靠开头的 `cloudEnvId: ''` 的空字符串换成你的环境 ID。只改这一处：`app.js` 启动时自动读它并初始化云开发，其他文件不用动。

> 官方依据：微信云开发《控制台》https://developers.weixin.qq.com/miniprogram/dev/wxcloud/guide/console.html ——控制台有数据库、存储管理、云函数等模块；小程序端用 `wx.cloud.init({ env: '环境ID', traceUser: true })` 初始化。
> 需核实：测试号能否开通云开发、免费额度多少——以开发者工具内实际提示为准。

---

## 第二部分：创建云数据库集合

1. 在开发者工具里点「云开发」打开**云开发控制台**，进**数据库**。
2. 点"添加集合"，逐个创建下面 13 个集合（名字必须一字不差）：
   `users`、`contacts`、`receiveEvents`、`receiveRecords`、`giftRecords`、`shareMemberships`、`shareGrants`、`auditLogs`、`importJobs`、`exportJobs`、`inviteBindings`、`inviteRewardGrants`、`appConfig`
3. 每个集合的字段长什么样，对照 `docs/数据字典.md`（第 2 部分）。
4. 权限先保持默认，**不要**设成"所有人可读写"——礼单簿的权限是服务端代码（`core/authz.js`）逐条校验的，数据库层面收紧更安全。**具体权限方案联调时再定（需核实）**
5. 邀请奖励防刷用的**设备指纹**目前是本地占位 id（`miniprogram/services/data-service.js` 的 getDeviceId，本地随机生成）。真机联调时定采集口径（设备信息组合或云端风控信号），只换生成方式，`core/invite-reward.js` 的校验逻辑不动。**具体口径联调时再定（需核实）**。

---

## 第三部分：部署云函数 api

1. 把仓库 `core/` 整个文件夹和 `miniprogram/config/app-config.js` **复制**进 `cloudfunctions/api/` 目录（云函数在云端跑，需要这些代码在身边）。
2. 打开 `cloudfunctions/api/index.js`，把注释掉的示例代码取消注释，按 `docs/接口文档.md` 把 action 分发写全。
3. 在开发者工具里，右键 `cloudfunctions/api` 目录 → **「上传并部署：云端安装依赖」**，等提示成功。
4. 去云开发控制台 → **云函数**，确认 `api` 在列表里且状态正常。

> 官方依据：微信开放文档《云函数》https://developers.weixin.qq.com/miniprogram/dev/wxcloud/guide/functions.html ——"只需编写函数代码并部署到云端即可在小程序端调用"；小程序端调用云函数时会自动带上用户 openid，"开发者无需校验 openid 的正确性"。
> 需核实：云函数 Node.js 版本选哪个——以控制台可选版本为准。

---

## 第四部分：小程序端切换到云（联调）

1. 小程序里原来调的是本地 `core/`（内存假数据），现在逐个改成 `wx.cloud.callFunction({ name: 'api', data: { action: '...', params: {...} } })`。
2. 对照 `docs/接口文档.md`，一个 action 一个 action 地接，先接"新增联系人""新增收礼记录"这种核心链路。
3. 每接完一个，在模拟器里点一遍，再去云控制台数据库里看数据真写进去了没有。

---

## 第二部分：必须等云环境的 5 项，逐项怎么验证

> 以下 5 项在沙箱里都没法验（报告里单列过），云环境就绪后按下表逐项打勾。

| # | 验证项 | 怎么验（大白话） | 通过标准 |
|---|---|---|---|
| 1 | CloudDB 真实读写 | ①控制台数据库里手动加一条 `contacts` 记录，看小程序亲友录里能不能显示；②小程序里新增一条收礼记录，去控制台看有没有落库 | 两边互相看得见 |
| 2 | 云函数 api 端到端 | ①控制台→云函数→`api`→云端测试，发 `{action:'contact.create', params:{...}}` 看返回；②小程序里点"新增亲友"走真实调用 | 测试和真机都返回成功 |
| 3 | `cloud.getWXContext()` 取 openid | 云函数里加一行测试代码返回 `cloud.getWXContext().OPENID`，**真机预览**下调用，看返回的 openid 是否每次一致 | 能稳定拿到 openid |
| 4 | 真实云数据库并发/权限 | ①两台手机同时往同一礼薄加记录，看两条都写进去了没丢；②用没被授权的微信号调接口，看是不是被拒绝（`core/authz.js` 的逻辑） | 不丢数据、越权被拒 |
| 5 | `wx.cloud.callFunction` 真实调用链 | 从小程序按钮点下去 → 云函数 → 数据库 → 返回显示，全链路走一遍，看模拟器调试器 Network 面板 | 全链路无报错、数据正确 |

> 官方依据：云函数自动注入 openid 见《云函数》文档（第三部分已引）；`wx.cloud.init` 见《云开发控制台》文档。
