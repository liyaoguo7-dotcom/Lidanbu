# 横置礼单本 · 实现方式说明

> 2026-10-20，随「留白边框」效果图（12–18）一并交付。本文只写已从微信官方文档核实的能力；没核实的统一标注「待联调验证」。

## 一、现状

- 横置礼单本目前**只有效果图，没有页面代码**：`docs/wireframes/landscape/` 下 01–18 均为静态 HTML/PNG。
- `miniprogram/` 里没有横置页面；现有页面都是竖屏。实现横置页属于新写页面，不是对现有页面的改造。
- 本轮留白结构（上/下留白 48px、左右窄留白 9px、标题居中、＋在下留白右侧）是公共结构，实现时一套布局组件换主题变量（颜色+纹路）即可，不按主题各写一套。

## 二、开启横屏：pageOrientation（已核实，微信官方文档《响应显示区域变化》）

- 在**页面级 json**（或 app.json 的 window 段）配置 `pageOrientation`：
  - `"auto"`：页面随设备方向旋转，显示区域尺寸随之变化。基础库 **2.4.0** 起支持手机屏幕旋转。
  - `"landscape"`：固定横屏显示。基础库 **2.5.0** 起支持。
  - 默认 `"portrait"`。
- iPad 另有要求：app.json 配置 `"resizable": true`（基础库 2.3.0 起），且 iPad 上不能按单个页面配置是否旋转。

**本项目取舍（建议 auto，不用 landscape 固定）**：指令要求「竖着拿先进页面、看到提醒条；转成横屏后才出现卷轴」——这是同一页面的两种状态。配 `landscape` 会强制横屏、不存在竖屏状态，提醒条就没有意义。所以横置页应配 `"auto"`，靠尺寸判断切换两种布局（见第三节）。

## 三、横竖屏判断与状态切换（已核实）

- 页面生命周期 **`onResize(res)`**（基础库 2.4.0 起）：尺寸变化时回调，`res.size.windowWidth / windowHeight` 为新显示区域尺寸。`windowWidth > windowHeight` 即横屏态，否则竖屏态。
- 自定义组件内用 `pageLifetimes.resize` 监听；另有 `wx.onWindowResize`（官方文档注明「不是推荐的方式」）。
- 也可以用 WXSS 的 media query、`match-media` 组件或 `this.createMediaQueryObserver()` 做纯样式层切换；但卷轴/提醒这类结构增减，用 `onResize + setData` 一个状态位（如 `isLandscape`）控制条件渲染最直接。
- **提醒条**：竖屏态显示，点 × 后「本次不再出现」——用页面内变量记录即可，不需要持久化存储（离开页面再进来可重新提示；如产品要改成永久不再提示，再改走本地存储，此点待产品确认口径时再定，效果图按「本次」处理）。
- **卷轴**：横屏态显示，竖屏态不渲染。切换动画只能做淡入/淡出过渡，布局重排本身是即时的；转屏时是否闪烁、过渡是否顺滑，**待联调验证**（开发者工具模拟与真机旋转行为有差异，最终以真机为准）。

## 四、安全区（刘海屏/挖孔屏）

- 已核实：可用 `wx.getWindowInfo()` 读取 `safeArea`（旧接口 `wx.getSystemInfoSync().safeArea` 已拆分合并到新接口），据此计算内容应避让的左右/上下偏移。
- 实现要点：横屏时刘海/挖孔多落在左右两侧——左右留白宽度取 `max(9px, safeArea 左/右偏移)`；＋按钮和纸面不得进入非安全区，安全区不够时优先保＋按钮可点。
- 本页顶栏是自绘的（返回箭头＋居中标题组），横屏下微信胶囊按钮（右上角）位置会随方向变化，标题居中组与胶囊的避让距离**待联调验证**；实现时用 `wx.getMenuButtonBoundingClientRect()` 取胶囊位置校验，不写死。
- CSS `env(safe-area-inset-*)` 在 WXSS 中的可用性**待联调验证**；稳妥做法是 JS 读 safeArea 后以样式变量注入。

## 五、已知限制（点名）

1. 基础库低于 2.4.0 的微信版本不支持页面旋转：`pageOrientation: "auto"` 不生效，页面保持竖屏（会一直停在竖屏态＋提醒条）。需在小程序最低基础库版本设置里权衡，或对低版本用户给出升级提示——**具体占比与提示方式待联调验证后定**。
2. 部分安卓机型需系统开启「自动旋转」页面才随转，且不同厂商 ROM 表现不一（社区有反馈），**待联调验证**，需备真机矩阵（至少主流安卓＋iPhone 各一台带刘海/挖孔机型）。
3. `pageOrientation` 只作用于配置了它的页面；从横置页返回竖屏页时方向恢复的行为**待联调验证**。
4. iPad 旋转需 app.json 全局 `resizable`，无法按页控制；iPad 上横置页的实际宽高比与手机不同（更接近方形），列数与列宽需按窗口宽度自适应，**待联调验证**。
5. 字体走「替代 A：常用字预生成包」（已定方案），横竖屏切换不影响字体加载；系统字体回退在安卓/iOS 上的表现差异**待真机验证**（与既有待办一致）。
