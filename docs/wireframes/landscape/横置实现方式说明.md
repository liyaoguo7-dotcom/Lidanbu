# 横置礼单本 · 实现方式说明

> 2026-10-20 更新，随「只支持横屏」效果图（23–31）一并交付。本文只写已从微信官方文档核实的能力；没核实的统一标注「待联调验证」。
> 本版变更：横置礼单本改为**只支持横屏**——竖屏不再显示窄版礼单本，改为整页「请横屏」提示（30 号图）；**卷轴由可选装饰改为横屏常驻**；原「竖拿提醒条」（17 号图）方案作废，文件已删。

## 一、现状

- 横置礼单本目前**只有效果图，没有页面代码**：`docs/wireframes/landscape/` 下 01–16、18、23–31 均为静态 HTML/PNG。
- `miniprogram/` 里没有横置页面；现有页面都是竖屏。实现横置页属于新写页面，不是对现有页面的改造。
- 留白结构（上/下留白 48px、左右窄留白 9px、标题居中、＋在下留白右侧）是公共结构，实现时一套布局组件换主题变量（颜色+纹路）即可，不按主题各写一套。
- 本轮图组：23–29 为横屏礼单本（5 种配色收礼 + 白事 + 送礼传统经典），全部带常驻卷轴与主题纹路；30 为竖屏「请横屏」页；31 为三字体网格对比（设计验证图，非运行时页面）。

## 二、开启横屏：pageOrientation（已核实，微信官方文档《响应显示区域变化》）

- 在**页面级 json**（或 app.json 的 window 段）配置 `pageOrientation`：
  - `"auto"`：页面随设备方向旋转，显示区域尺寸随之变化。基础库 **2.4.0** 起支持手机屏幕旋转。
  - `"landscape"`：固定横屏显示。基础库 **2.5.0** 起支持。
  - 默认 `"portrait"`。
- iPad 另有要求：app.json 配置 `"resizable": true`（基础库 2.3.0 起），且 iPad 上不能按单个页面配置是否旋转。

**本项目取舍（用 auto，不用 landscape 固定）**：「只支持横屏」指的是礼单本内容只在横屏显示，但同一页面必须有竖屏状态来承载「请横屏」提示页。配 `landscape` 会强制横屏、竖屏提示页无从出现，且用户被方向锁定挡住时没有任何引导。所以横置页配 `"auto"`，靠尺寸判断在同一页面切换两个状态（见第三节）：竖屏 = 请横屏页，横屏 = 礼单本。

## 三、横竖屏判断与状态切换（已核实）

- 页面生命周期 **`onResize(res)`**（基础库 2.4.0 起）：尺寸变化时回调，`res.size.windowWidth / windowHeight` 为新显示区域尺寸。`windowWidth > windowHeight` 即横屏态，否则竖屏态。
- 自定义组件内用 `pageLifetimes.resize` 监听；另有 `wx.onWindowResize`（官方文档注明「不是推荐的方式」）。
- 也可以用 WXSS 的 media query、`match-media` 组件或 `this.createMediaQueryObserver()` 做纯样式层切换；但两态是整页结构替换（请横屏页 ↔ 礼单本），用 `onResize + setData` 一个状态位（如 `isLandscape`）控制条件渲染最直接。
- **切换顺序（本版新增要求）**：`onResize` 里先关闭已打开的半屏详情（点列弹出的那层），再切状态位渲染目标态，避免半屏残留在错误方向上。
- **平滑切换**：两态切换只能做淡入/淡出过渡，布局重排本身是即时的；目标是转屏不闪白、不残影——开发者工具模拟与真机旋转行为有差异，是否平滑**待联调验证**，最终以真机为准。
- **请横屏页（竖屏态，30 号图）**：整页只出现提示，不渲染礼单本（不显示窄版、不留提醒条）。固定内容：顶部返回箭头；居中旋转手机线条图标；主提示「请把手机横过来，礼单本就会铺开啦」；次提示（小字灰）「横置礼单本仅支持横屏使用」；锁屏提示（小字灰）「没有反应？请先在手机控制中心关闭"竖屏锁定"」；底部次要按钮「切换回竖置样式」（点了回普通竖置礼单，数据不丢）。
- **卷轴（横屏态常驻）**：横屏礼单本左右各一根半透明卷轴，同色系、带主题淡纹路与高光，为纯装饰层、不拦截点击；竖屏态不渲染。此条取代旧版「卷轴为可选装饰层」的说法。

## 四、竖屏锁定与平台限制

- 用户开了系统方向锁定（iOS 控制中心「竖屏锁定」、安卓关掉「自动旋转」）时，页面旋转不会发生：页面会一直停在竖屏态的请横屏页，`onResize` 不触发——这正是请横屏页要常驻一行锁屏提示的原因（文案见第三节，逐字使用）。
- 安卓：部分机型需系统开启「自动旋转」页面才随转，且不同厂商 ROM 表现不一（社区有反馈），**待联调验证**，需备真机矩阵（至少主流安卓＋iPhone 各一台带刘海/挖孔机型）。
- iOS：控制中心竖屏锁定开启时不旋转；微信内页面方向还受宿主方向影响，具体表现**待联调验证**。
- 两平台都无法由小程序主动探测「是否开了方向锁定」，也无法代用户关闭；只能停留在请横屏页等待用户处理后自动切换（用户关掉锁定并转横后，`onResize` 触发即进礼单本，无需刷新）。

## 五、安全区（刘海屏/挖孔屏）

- 已核实：可用 `wx.getWindowInfo()` 读取 `safeArea`（旧接口 `wx.getSystemInfoSync().safeArea` 已拆分合并到新接口），据此计算内容应避让的左右/上下偏移。
- 实现要点：横屏时刘海/挖孔多落在左右两侧——左右留白宽度取 `max(9px, safeArea 左/右偏移)`；＋按钮和纸面不得进入非安全区，安全区不够时优先保＋按钮可点。常驻卷轴贴左右边缘，安全区偏移较大时卷轴与纸面的相对位置**待联调验证**。
- 本页顶栏是自绘的（返回箭头＋居中标题组），横屏下微信胶囊按钮（右上角）位置会随方向变化，标题居中组与胶囊的避让距离**待联调验证**；实现时用 `wx.getMenuButtonBoundingClientRect()` 取胶囊位置校验，不写死。
- CSS `env(safe-area-inset-*)` 在 WXSS 中的可用性**待联调验证**；稳妥做法是 JS 读 safeArea 后以样式变量注入。

## 六、已知限制（点名）

1. 基础库低于 2.4.0 的微信版本不支持页面旋转：`pageOrientation: "auto"` 不生效，页面保持竖屏（会一直停在请横屏页）。需在小程序最低基础库版本设置里权衡，或对低版本用户给出升级提示——**具体占比与提示方式待联调验证后定**。
2. `pageOrientation` 只作用于配置了它的页面；从横置页返回竖屏页时方向恢复的行为**待联调验证**。
3. iPad 旋转需 app.json 全局 `resizable`，无法按页控制；iPad 上横置页的实际宽高比与手机不同（更接近方形），列数与列宽需按窗口宽度自适应，**待联调验证**。
4. 字体走「替代 A：常用字预生成包」（已定方案），横竖屏切换不影响字体加载；系统字体回退在安卓/iOS 上的表现差异**待真机验证**（与既有待办一致）。三款已确认字体（霞鹜文楷/马善政毛笔体/龙藏体）对本轮 45 个示例字符的 cmap 覆盖已查：**全部无缺字**（fonttools 实查，含欧阳修远与大写金额全套）。
