# 数据字典（T1.1）

> 基线：v3.1 §17.2 ｜ 金额一律整数"分" ｜ 不设 RecycleBin、不设 ReceiveProject

## users（用户）

| 字段 | 类型 | 说明 |
|---|---|---|
| _id | string | openid（云开发 `getWXContext` 获取） |
| inviteCode | string | 我的邀请码（8 位，懒生成、全局唯一；老用户可为空直到首次打开邀请页） |
| membership.status | string | free / member |
| membership.expireAt | number | 会员到期时间戳；free 为 null |
| membership.graceUntil | number | 缓冲期结束（派生，冗余存储可为空） |
| pointsBalance | number | 积分余额（任务P1）；与 pointsLedger 流水同口径维护，缺省 0；积分不过期、会员到期后保留 |
| cancelStatus | string | 注销状态：'pendingCancel' = 已申请注销、冷静期内；其余为空（任务L） |
| cancelApplyAt | number | 注销申请时间戳（未申请为空） |
| cancelAt | number | 冷静期满执行注销的时间戳（= 申请 + 配置 coolingOffDays，默认 7 天） |
| restricted | object | 异常用户限制标记（任务M，可空）：{status:boolean, reason, by(管理员), at}；status=true 时核心写入口全拦（只拦写不拦读） |
| profile.nickname | string | 昵称（任务Q1）：空串 = 未设置；不设单独的"名字"字段。显示名一律在读取时由 core/users.displayName 解析（昵称非空用昵称，否则显示"微信用户"），记录里只存记账人 openid（createdBy），改昵称后历史记录的"谁记的"同步显示新名 |
| profile.avatarUrl | string | 头像地址（任务Q1）：页面层用微信头像选择能力拿到路径/云文件 ID 后传入，只存字符串，core 不校验内容 |
| privacyConsent.agreed | boolean | 是否已同意隐私政策/用户协议（任务Q1）：缺省 = 未同意。口径：同意状态只做记录与展示（首次弹窗同意、"我的—隐私"可查），**不作任何功能的门禁**，未同意不拦截拍照导入/记账/浏览等任何功能 |
| privacyConsent.agreedAt | number | 同意时间戳（撤回同意时清空） |
| privacyConsent.version | string | 同意时的政策版本，取配置 AppConfig.legal.privacyVersion（初值 v1） |
| createdAt | number | |

> 昵称敏感文字检测（任务Q1）：走 core/content-safety.js 适配层——接口 {checkText(text)→{pass}}，实现有本地词表 Mock（词表在配置 AppConfig.contentSafety.localBlocklist，默认空）与微信 msgSecCheck 骨架（云联调后经云函数接入）。适配层异常时口径为放行并记审计（不因检测服务故障堵死改名），不合规则拒绝修改。

## inviteBindings（邀请关系绑定记录）

每位被邀请人最多一条；账号注销清理时**不删除**（与发放记录一起防止"注销后重注册重复计数"）。只存 id/邀请码/时间，不存账本内容。

| 字段 | 类型 | 说明 |
|---|---|---|
| _id | string | |
| inviterId | string | 邀请人 |
| inviteeId | string | 被邀请人 |
| code | string | 绑定用的邀请码 |
| deviceId | string\|null | 设备指纹占位（可注入；真机采集待联调） |
| status | string | 'bound' 已绑定待完成条件 \| 'granted' 已发放 \| 'blocked' 设备重复被拦 |
| boundAt | number | 绑定时间 |
| grantedAt | number\|null | 发放时间 |

| 字段 | 类型 | 说明 |
|---|---|---|

## orders（会员购买订单，任务K）

支付链路：建单（pending）→ 适配层调起支付 → 回调验单发货（置 paid 并给 users.membership 续期）。金额/天数是下单时从生效档位（老板平台 appConfig.pricing 优先，否则静态占位价）取的快照，改价不影响已下单。同一 outTradeNo 重复回调只发货一次；回调金额与快照不一致拒绝发货。退款为占位处理（置 refunded + 按未消耗整期回收会员时长 + 审计），真实退款待支付接入。

| 字段 | 类型 | 说明 |
|---|---|---|
| _id | string | |
| userId | string | 购买人（订单只对本人可见） |
| planId / planName | string | 档位 id / 名称快照 |
| amountFen | number | 金额快照（分） |
| days | number | 购买天数快照 |
| grantPoints | number | 赠送积分快照（任务P1）；发货时经 points.grant(kind='plan_grant', refId=outTradeNo) 幂等入账；退款时余额足够才整额回收（plan_grant_reversal） |
| status | string | pending / paid / failed / cancelled / refunded |
| channel | string | mock（模拟）/ wxvirtual（微信虚拟支付，骨架未接） |
| outTradeNo | string | 业务单号，唯一，回调按此对单 |
| channelTradeNo | string\|null | 渠道单号 |
| createdAt / paidAt | number\|null | 建单 / 支付成功时刻 |
| baseAt / prevExpireAt / deliveredExpireAt | number\|null | 发货叠加基准 / 发货前到期 / 发货后到期时刻（退款回收依据） |
| refundedAt / reclaimedDays | number\|null | 退款时刻 / 回收的会员天数 |

## pointsLedger（积分流水，任务P1）

余额的对账真源：每一笔积分变动记一条流水，users.pointsBalance 与流水末笔 balanceAfter 始终一致（记账顺序写；云端须事务）。幂等铁律：同一 (userId, kind, refId) 只入账一次，重复点击/重复回调/网络重试不多加不多扣；返还以原 refId+':refund' 为冲正键，只退一次且不超过原扣。

| 字段 | 类型 | 说明 |
|---|---|---|
| _id | string | |
| userId | string | 积分账户主人 |
| delta | number | 正=入账，负=消耗 |
| balanceAfter | number | 本笔后余额 |
| kind | string | register_grant 注册赠送 / plan_grant 套餐赠送 / plan_grant_reversal 退款回收赠送 / pack_purchase 积分包入账 / photo_import 拍照消耗 / photo_refund 拍照返还 / manual 人工 |
| refId | string | 订单号 / jobId 等业务键（幂等键、流水对账用） |
| note | string | 摘要 |
| createdAt | number | |

## invitations / rsvps（已下线，2026-10-21）

自制电子请柬已按用户决定取消：`invitations`（电子请柬）与 `rsvps`（请柬回执）两集合已从 `core/models.js` 删除，代码与页面全部下线，云端初始化清单同步移除（不再新建这两集合）。首页「电子请柬」入口改为跳转合作小程序（配置 `AppConfig.externalInvitation`，AppID 待用户提供）。4 种风格效果图仅作设计存档保留在 `docs/wireframes/invitation/`。
