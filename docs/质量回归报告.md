# 礼单簿 · 质量回归报告（任务N，2026-10-21）

> 方法：静态审计全仓 WXSS/WXML/文案 + 全套自动化测试。本报告只写静态能证明的事；
> 凡需要真机的，一律列入"待真机验证"，不冒充已验。
> 审计范围：55 个页面（app.json 主包 42 页＋分包）＋全部组件。

## 一、尺寸适配

| 项 | 结论 | 证据/说明 |
|---|---|---|
| 360px 小屏不溢出 | ✅ 静态通过 | 全仓 WXSS 无 `width > 340px` 的写死宽度（脚本扫描 0 命中）；布局一律 flex/百分比/rpx，卡片左右留 12px、表单行弹性伸缩 |
| 大屏/平板 | ⚠️ 可接受、列待办 | 无 max-width 收拢：平板上卡片会拉满宽。产品定位手机竖屏，横置 iPad 适配本就列在《横置真机联调清单》后续项，不在本轮 |
| 刘海屏 safe-area（竖置页） | ✅ 本轮补齐 | 此前竖置页无 env() 兜底（横置页走 JS 读 `wx.getWindowInfo` 注入，不变）。本轮给 9 处贴底元素加 `calc(原值 + env(safe-area-inset-bottom))`（保留原值作不支持 env 时的回退行）：`app.wxss` 的 `.btn-bottom`、`.fab`；gift-detail / receive-detail / receive-record-detail 的 `.bottom-btns`；import-review 的 `.picker-sheet`；contacts 半屏 `.sheet`；contact-sheet / contact-edit-sheet 组件 `.sheet` |
| 刘海屏（横置页） | 已有方案 | JS 安全区注入（`landscape-core.js` 的 `USE_ENV_SAFE_AREA=false` 开关），真机数值待《横置真机联调清单》第 3 条验证 |

## 二、可点区域 ≥44px（88rpx）

全仓扫描出 37 条"高度 <44px"的规则，逐条定性：34 条是图标/圆点/分割线/印记等**非可点装饰**（其所在行/格才是点击目标）；
真正以小元素本身承接点击的 3 处已修：

| 位置 | 原状 | 修法 |
|---|---|---|
| 竖线树钢笔图标 `.tpen`（timeline.wxss） | 图标 28rpx 本体承接 bindtap | 本体不变，padding 扩可点区到 88rpx 见方＋负 margin 抵消布局位移，版式与定版图一致 |
| 请柬回执人数步进 `.step-btn`（guest.wxss） | 30px 圆钮 | 放大为 44px 圆钮 |
| 反馈截图删除叉 `.fb-del`（feedback.wxss） | 22px 圆徽本体承接点击 | 本体扩为 44px 透明可点区，可见圆徽由 ::after 画回原位（22px） |

已核查合规、无需改的：我的页横置开关（点的是整行 form-row 116rpx）、横置样式面板色块（点的是含名称的整格 .opt）、横置＋按钮（`.plus-touch` 本就是 44px 触控区、视觉 31px）、主按钮 `.btn-primary` 56px、表单行 58px、标签选择格（56px 圆＋文字整格可点）。
搜索框：真实页面用整行搜索区（输入框＋"取消"同行，行高含内边距 ≥44px）；独立 search-box 组件（72rpx）仅演示页引用，列真机抽查项。

## 三、系统字号

- 字号一律 px/rpx 定值，不随系统字号缩放——好处是版式不乱，代价是大字号模式下单行元素可能挤。
- 全仓 `white-space: nowrap` 只有 4 处，均为刻意单行：小喇叭滚动文案、横置列内文字（定版规格）、样式面板字体预览、搜索"取消"二字；无 `text-overflow: ellipsis` 截断姓名类内容，列表姓名均可换行。
- 结论：静态无写死 px 截断文本的问题；**真机待验**：系统字号调到最大时抽查小喇叭条、横置列、往来列表三处（列入上线前真机清单）。

## 四、弱网/离线

- 本地模式（现行默认）：数据全在本机存储，断网可正常记账——天然离线可用，无需联网。
- 本轮落地：①`app.js` 新增网络状态监听：启动与断网变化时给一句大白话提示（本地模式："现在没有网络，礼单簿可以先记在本机，数据都在你的手机里"；云模式："现在没有网络，联网后再试一次吧"），只在状态变化时提示一次。
- ②`data-service.friendly()` 新增网络错误识别：云函数/请求失败类错误统一翻成"网络不太顺，请检查网络后再试一次"，不透内部报错（`tests/test-offline-hint.js` 2 个用例：网络错误命中、业务错误不误判）。
- 待云联调：云模式下断网时的页面级表现（列表读失败的占位与重试按钮）随云联调一起验，本轮不假造"已存本机"类承诺文案。

## 五、状态文案（空/加载/错误）

- 全仓空状态文案逐条扫过：均为大白话（"还没有礼薄，点击下方红色＋按钮添加"等），无内部术语。
- 本轮修的 3 处用户可见内部说法：
  1. 邀请奖励页"收礼额度池"→"**收礼名额**"（3 处 wxml＋1 处 js 文案；老板平台是运营端，保留原术语不动）；
  2. 邀请奖励页规则文案还是旧口径"记 1 条收礼/送礼"，已改为确认口径"添加一位收礼亲友/送礼亲友，用这位亲友记上一笔"；
  3. 报错出口统一经 `friendly()`：业务文案（额度/权限/会员等）原样透出，未知错误只给"操作失败，请重试"，报错码不直达用户（test-amount-scan 与 errors 映射既有覆盖）。
- 隐私政策页里的 openid 等词是给用户解释用的大白话说明（"微信给每个用户的一串匿名编号"），属主动披露，保留。

## 六、性能（静态证据）

- 横置礼单本：窗口化渲染已实现（`landscape-core.windowRange`，只渲染可视列±2 缓冲，占位撑几何；test-landscape「横置-窗口化」覆盖）。
- 长列表（往来/竖线树/记录/通知/亲友）：全量渲染。数据规模被额度上限天然封顶（免费：每薄 30 条/亲友 50；会员占位上限 500），静态判断可接受；**真机待验**：中低端安卓在 500 条量级下的滚动流畅度，列入真机清单；若不过，后续加分页/虚拟列表（本轮不预先复杂化）。
- 字体：分包按需下载＋缓存（font-source 适配层三级来源），不堵首屏。
